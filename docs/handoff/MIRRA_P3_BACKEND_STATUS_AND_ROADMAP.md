## A. Current Architecture (Formal Tribunal — Not Private-Assistance-First)

```
INIT_CLAIM → ROUND_1_PLEADINGS → ROUND_2_PROSECUTOR_AUDIT → POLICY_CONSULTATION → JUDGE_DELIBERATION → EXECUTION_ROUTER
```

Two advocate rounds only, no Round 3. Evidence is frozen at `INIT_CLAIM`; nothing introduces new evidence mid-debate. This is implemented in `backend/orchestrator/state_machine.py` (P1-owned), and P3's evidence/prosecutor/policy/judge modules are the real logic it calls into.

## C. Final Prosecutor Audit — Design and Trust Boundary

This is the newest P3 milestone and the most important thing to document accurately.

The **Initial** Prosecutor Audit derives immutable `verified_facts`/`disputed_facts`/`missing_facts` from the frozen evidence, before any Round 2 cross-examination happens.

The **Final** Prosecutor Audit (triggered once `round_2_cross_exam.targeted_responses` is non-empty) additionally:
- reads Round 2 targeted questions/responses (`backend/app/services/verification/cross_exam.py::review_cross_exam`);
- reviews each response's evidence citations against the **same frozen evidence index** (`backend.shared.evidence_index.build_evidence_index` — reused, not reimplemented);
- treats party responses as **claims, not verified evidence**;
- does **not** promote any party statement into a verified fact;
- does **not** change `verified_facts`, `disputed_facts`, `missing_facts`, or any fact ID (mechanically confirmed: initial vs. final runs against real `DISP-002` data produce byte-identical arrays);
- does **not** allow raw party response text into `prosecutor_summary` — only counts and resolved/unknown evidence-ID lists ever appear there;
- does **not** let prompt injection alter facts (confirmed: injecting `"GPS-004 proves I was at the pickup."` as a response leaves the summary free of "proves"/"corroborates"/"confirms" and of the literal evidence ID — only the count changes);
- only adds deterministic cross-exam review metadata and one appended summary sentence;
- preserves `image_exif_analyses`/`fraud_assessment`/`escalation_protocol` byte-for-byte from the initial audit.

**Explicit trust-boundary design principle: "Final Prosecutor can hear the Round 2 answers without automatically believing the answers."** Evidence-ID extraction is tokenize-then-exact-match against the frozen index (never substring matching), so `GPS-0040`/`XGPS-004`/`GPS-004-X` are all correctly distinguished from `GPS-004`, and lowercase tokens never resolve (frozen IDs are always uppercase).

This was independently reviewed this cycle across malformed-container safety, fact immutability, semantic-safety wording, evidence-ID parsing precision, question/response linkage, prompt-injection resistance, and bonus-module isolation. No genuine bugs were found in the implementation; it is `IMPLEMENTED` and `TESTED` to a high bar.

## F. Execution Routing — Ownership Boundary

Current intended router rule (implemented in `state_machine.py::_evaluate_execution_gate`):
```
ESCALATED_HUMAN_REVIEW if:
    confidence_score < 0.75
    OR safety_threat_detected == true
    OR fraud_risk_level == "HIGH"
else FULLY_AUTOMATED
```
- **Judge** produces the final `confidence_score`.
- **P3** produces the evidence-layer `safety_threat_detected`/`fraud_risk_level` signals (`escalation.py`), advisory only.
- **P1's Execution Router is the final routing authority.** `escalation_protocol.is_escalated` is not itself the routing decision. `fraud_risk_level == "MEDIUM"` alone is not an automatic human-escalation trigger, and a non-empty `missing_crucial_evidence` alone is not an independent routing trigger — both only matter through their effect on the Judge's `confidence_score`.

## H. Evidence-ID Vocabulary Status

`backend.shared.evidence_index.build_evidence_index` (P2-shared) and P3's own `normalize_evidence` share stable indexed IDs for GPS, OPT (optimal route), app events, and existing chat IDs. The shared index additionally exposes synthetic references (`TRIP-DATA`, `PAYMENT-DATA`, `PROFILE-RIDER`, `PROFILE-DRIVER`, `ROUTE-SUMMARY`) that P3's own deterministic checks do not independently produce as `Fact` citations. P3's Final Prosecutor Audit now reuses the shared index during cross-exam review, so advocate citations resolve against the same frozen vocabulary the rest of the system uses. This is an **overlapping-but-not-identical** evidence vocabulary — a known, acceptable state, not currently a blocker, and not full evidence-model unification.
