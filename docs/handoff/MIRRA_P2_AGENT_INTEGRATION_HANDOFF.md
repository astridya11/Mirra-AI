## C. Round 1 — Advocate Behavior (Verified)

Rider/Driver `generateResponse` implements the following safety-critical, deterministic contract on top of the LLM call:

- **Claimant's requested amount is capped to the disputed amount** — an LLM cannot request more than the case's actual disputed amount, no matter what it outputs.
- **Respondent's requested amount is forced to zero** — the responding party in a dispute cannot be given a nonzero requested amount by the LLM.
- **Evidence references must resolve against the shared evidence index** — any evidence ID the LLM cites that isn't in `build_evidence_index()`'s output is filtered out before the statement is returned. Nothing unresolvable reaches the `AgentStatement`.
- **Prompt injection cannot override the deterministic amount cap** — confirmed by dedicated tests that inject adversarial prompt text attempting to raise the requested amount; the cap still applies.
- **Wrong-target questions return safely** — if a Round 2 question is directed at the other party, `generateResponse` does not fabricate a response on their behalf.

All of the above is `TESTED`, both via pytest (`backend/tests/test_prosecutor_agent.py` and related) and via the standalone `backend/tests/test_advocates.py --mock` script (confirmed passing this session, including its explicit "injection did not override the cap" assertion).

## D. Round 2 — Prosecutor Audit & Cross-Examination

### Initial Prosecutor Audit (IMPLEMENTED, TESTED)
Derives `verified_facts`/`disputed_facts`/`missing_facts` from the frozen evidence, plus `bonus_modules` (image/EXIF analysis, fraud assessment, escalation signals — all P3-owned, see the P3 roadmap doc).

### Final Prosecutor Audit (IMPLEMENTED, TESTED)
`prosecutor_agent.py` detects whether `round_2_cross_exam.targeted_responses` is non-empty and, if so, runs a **Final** audit instead of an Initial one. The Final Audit:
- reviews Round 2 targeted questions/responses against the same frozen evidence index (`backend/app/services/verification/cross_exam.py`);
- treats every advocate response as an **unverified claim**, never as new evidence;
- never changes `verified_facts`, `disputed_facts`, `missing_facts`, or any fact ID;
- never copies raw response text into `prosecutor_summary` — only counts and resolved evidence IDs;
- appends a deterministic cross-exam summary sentence to `prosecutor_summary` and leaves `image_exif_analyses`/`fraud_assessment`/`escalation_protocol` byte-for-byte unchanged.

This was independently reviewed this development cycle (adversarial prompt injection, malformed Round 2 containers, evidence-ID substring collisions, fact-immutability) with no bugs found. See the P3 roadmap doc, Section on Final Prosecutor Audit, for the full design rationale.

## E. Judge / Policy Contract (Verified Implemented)

- **Policy Consultant** (`run_policy_consultation`) reads `backend/policy/ryde_policy_v1.json` (the real Ryde policy clause library, POL-1..POL-9, each with computable `params`) plus a growable precedent store (`backend/policy/precedent_store.py`), and returns a `PolicySuggestion`: `applicable_clauses`, `matched_precedents`, `suggested_ruling_type`, `suggested_recommended_action`, `policy_confidence`.
- **A precedent can never override a policy clause** (POL-8) — enforced in `policy_consultant_agent.py`: when the policy computation reaches a conclusion, it wins outright; precedents only fill gaps or add rationale color when the computation can't reach one.
- Precedents are only created from a human `MODIFIED`/`OVERRIDDEN` decision with a reason during `ESCALATED_HUMAN_REVIEW` (not from `REJECTED_AUTO`), and only an **approved** precedent is citable — this is the learning-feedback loop, and it is implemented, not a schema-only concept.
- **Judge** (`run_judge`) consumes `context["policy_consultation"]["suggestion"]` — it does **not** independently recompute policy. It cannot invent monetary amounts (verified: an LLM-invented refund amount was overridden in a direct unit test to the policy suggestion's own figure). Invalid fact citations and invalid clause/precedent references are filtered out of the final verdict. A missing policy consultation fails safe. Policy disagreement between the Judge's own reasoning and the suggestion caps confidence rather than silently picking one side. An `ESCALATED` verdict's `confidence_score` is always below the automation threshold. **The Judge is the sole final producer of `confidence_score`** — nothing downstream recomputes it.

Do not document Policy or Judge as unimplemented. Do not invent a different policy source than `ryde_policy_v1.json` + the precedent store.

**Separate and still empty, do not confuse the two:** `backend/app/services/verification/policy.py`'s `_POLICY_REGISTRY` (used only by the evidence-layer `check_policy_eligibility` check inside P3's deterministic verification engine) remains intentionally empty — that check still always returns `MISSING`. This is unrelated to the real Judge/Policy Consultation path described above, which is fully implemented and does not use that registry at all.
