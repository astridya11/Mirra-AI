## A. Current Product Architecture — Formal Tribunal

The current, agreed workflow has **no informal "Private AI Assistance first" stage**. Every case goes straight into the formal Tribunal pipeline. Do not build or describe a private pre-Tribunal assistance chat as the current architecture — that concept is retired.

```
INIT_CLAIM
→ ROUND_1_PLEADINGS
→ ROUND_2_PROSECUTOR_AUDIT
→ POLICY_CONSULTATION
→ JUDGE_DELIBERATION
→ EXECUTION_ROUTER
```

There are exactly **two** advocate rounds, no Round 3:

- **Round 1:** Rider Advocate presents the rider's case; Driver Advocate presents the driver's case.
- **Round 2:** (1) Initial Prosecutor Audit → (2) Prosecutor generates targeted cross-examination questions → (3) Rider/Driver Advocates answer the questions directed at them → (4) Final Prosecutor Audit → (5) Policy Consultation → (6) Judge Deliberation → (7) Execution Router.

**Evidence is frozen at case filing (`INIT_CLAIM`).** No new evidence is introduced during Round 1 or Round 2 — advocates and the Prosecutor only ever reason over the same frozen `data_sources`.

This is implemented, not just documented: `backend/orchestrator/state_machine.py` defines a `State` enum with exactly these six phases and a `PipelineEngine` that walks a `CaseContext` through them via `run_dispute_pipeline_realtime()`.

## D. Current P1 Blockers

### Blocker A — `backend/main.py` imports deleted pipeline functions (HIGHEST PRIORITY)

```python
from backend.orchestrator.state_machine import (
    ...
    run_dispute_pipeline,
    run_dispute_pipeline_with_events,
)
```

Neither name exists in `backend/orchestrator/state_machine.py` anymore. The current orchestrator exposes `run_dispute_pipeline_realtime(...)` instead (an async generator / realtime streaming entry point — see `PipelineEngine` and its `_stream_*` phase methods). Importing `backend/main.py` currently raises `ImportError` at module load, which breaks the app. **This is the single biggest blocker to a real end-to-end run** — nothing downstream can be exercised through the actual FastAPI app until this is fixed.

### Blocker B — `backend/main.py::get_case()` can reload a stale case

```python
def get_case(case_id: str) -> dict[str, Any] | None:
    file_path = _MOCK_DATA_DIR / f"{case_id}.json"
    if not file_path.exists():
        return None
    with open(file_path, "r", encoding="utf-8") as f:
        return json.load(f)
```

This always reads the original raw fixture from `mock_data/`, even after a pipeline run has completed and `save_case()` has written the finished result (with `judge_verdict`, `execution_payload`, etc.) into the in-memory `_completed_results` dict. Human-review / learning-feedback flows that call `get_case()` after completion risk operating on the pre-Tribunal raw case instead of the actual completed one. **Fix should check `_completed_results` first, then fall back to the raw mock file.**

### Blocker C — Round 2 `directed_to` normalization gap

`state_machine.py::_normalize_live_question` (around line 455):

```python
"directed_to": raw.get("directed_to") or raw.get("target") or "BOTH",
```

Routing internally uses `target: "RIDER_ADVOCATE" | "DRIVER_ADVOCATE"`, but the schema's `TargetedQuestion.directed_to` expects `RIDER | DRIVER | BOTH`. If `generateQuestion` (once implemented by P2) returns only `target` and not an already-correct `directed_to`, this line stores the raw `"RIDER_ADVOCATE"`/`"DRIVER_ADVOCATE"` string into `directed_to`, producing a schema-invalid `TargetedQuestion`. Routing `target` and stored `directed_to` must stay distinct concepts — recommended fix is an explicit mapping (`RIDER_ADVOCATE`→`RIDER`, `DRIVER_ADVOCATE`→`DRIVER`) before assignment, not a bare fallback chain.

### Blocker D — `round2_completed` uses `setdefault`

`state_machine.py` (around line 603):

```python
self.ctx.round_2_cross_exam.setdefault("round2_completed", True)
```

`setdefault` only sets the key if it is **absent** — if the key already exists and is `False`, this line is a no-op and the value stays `False`. It should eventually be an explicit assignment (`self.ctx.round_2_cross_exam["round2_completed"] = True`) once Round 2 genuinely finishes.

None of these four were fixed in this documentation pass (per task scope: docs-only, no source changes). They are the four concrete items P1 should pick up first.

## F. Contracts P1 Must Preserve

- Do not reintroduce a third advocate round or a pre-Tribunal informal-assistance phase — both are explicitly retired design decisions.
- Do not let advocates or the Prosecutor introduce new evidence after `INIT_CLAIM` — the frozen-evidence rule is load-bearing for the Final Prosecutor Audit's trust model (see the P3 roadmap doc, Section G).
- Do not duplicate evidence-ID generation — always resolve through `backend.shared.evidence_index.build_evidence_index`.
- Do not have the orchestrator recompute policy independently — Policy Consultation is the sole policy source; the Judge only consumes `policy_consultation.suggestion`.
- Judge remains the sole producer of `confidence_score`. Do not have the Execution Router or orchestrator compute or override it.

## G. Execution Routing (Owned by P1)

`_evaluate_execution_gate()` in `state_machine.py` implements:

```
ESCALATED_HUMAN_REVIEW if:
    confidence_score < 0.75
    OR safety_threat_detected == true
    OR fraud_risk_level == "HIGH"
else FULLY_AUTOMATED
```

- Judge produces the final `confidence_score`.
- P3's evidence-layer modules (`fraud.py`, `escalation.py`) produce `safety_threat_detected` and `fraud_risk_level` as advisory signals inside `bonus_modules.escalation_protocol`.
- **P1's Execution Router is the sole final routing authority.** `escalation_protocol.is_escalated` is an evidence-layer signal, not a routing decision — do not treat it as equivalent to the router's own verdict. `fraud_risk_level == "MEDIUM"` alone must **not** be documented or implemented as an automatic human-review trigger, and a non-empty `missing_crucial_evidence` alone must **not** be treated as an independent routing trigger — both only matter insofar as they've already lowered the Judge's `confidence_score`.
